# 法規檢討資料（全條文）

外掛 `Rules\CodeCheck\` 的三個檔案由本資料夾的腳本產生：

| 檔案 | 內容 |
|---|---|
| `CodeCheck_Laws.json` | 官方條文全文：建築技術規則總則／設計施工／構造／設備編、建築物無障礙設施設計規範（108.07.01）、各類場所消防安全設備設置標準、建築法、建築物使用類組及變更使用辦法、都市計畫法、新建建築物節約能源設計標準、透水保水滯洪標準 |
| `CodeCheck_Rules.json` | 可執行規則（`rules_tw.py`），每條對應條號與門檻 |
| `CodeCheck_Catalog.json` | 每一條條文的檢討方式：自動／半自動／人工／非模型，以及對應規則 |

## 法規修正時

1. 下載全國法規資料庫開放資料 `ChLaw.json.zip`、`ChOrder.json.zip`，及無障礙規範 PDF，放到 `raw\`。
2. `python extract_laws.py` → `python build_codecheck.py out`
3. 比對 `rules_tw.py` 中受影響條文的門檻（build 時會列出找不到條號的規則）。
4. 把 `out\*.json` 複製到 `DevelopmentTools.Addin\Rules\CodeCheck\`；或先放在使用者電腦 `%APPDATA%\DevelopmentTools\CodeCheck\` 覆蓋（外掛優先讀使用者資料夾）。

## 規則語法

見 `rules_tw.py` 檔頭。變數由 `Modules\CodeCheck\ModelFacts.cs` 從模型讀出；運算式未定義的變數會在結果顯示「資料不足」並寫出缺少的變數名稱，不會中斷檢討。

## 辨識關鍵字

房間用途（走廊、樓梯間、臥室、廁所…）與設備（滅火器、消防栓、偵煙探測器…）依名稱關鍵字辨識，
設定檔在 `%APPDATA%\DevelopmentTools\CodeCheck\keywords.json`（第一次執行自動產生，可自行增修）。

## 拆檔合併檢討

主視窗「檢討範圍（模型）…」選擇要一起檢討的模型：

- **目前檔案**與其中**已載入的 Revit 連結**（含巢狀連結）自動列出。
- **未連結的模型檔**用「加入模型檔…」選取，檢討時在暫存交易中以共用座標連結（沒有共用座標則原點對原點），檢討結束交易回復，連結即消失，不修改任何檔案。該檔若正在 Revit 中開啟需先關閉。
- 每個模型可勾選要讀的內容：房間樓層／門窗／樓梯坡道欄杆／設備／車位／防火區劃。預設依檔名判斷：含 STR、結構 → 全不讀（仍參與淨高、梁下、管下高度射線）；含 MEP、機電、消防、給排水、空調、電氣 → 只讀設備；其餘視為建築模型全部讀取。
- 樓層：由有房間的模型提供，依高程合併（預設容許差 300 mm），名稱不同的同層會在報告「量測說明」列出；結構、機電模型的元素依高程對應到合併後的樓層。
- 重複元素：不同模型在同位置的房間（中心落在對方範圍內且面積差 10% 內）、門窗（25 cm 內）、樓梯（外框重疊 80%）、同類設備（15 cm 內）、車位只計一次。
- 門窗兩側房間在別的模型時，沿牆法線兩側探測房間邊界判定。
- 步行距離：合併檢討時改用「房間範圍＋門開口」網格（`WalkGrid.cs`，16 方向 Dijkstra），不依賴 Revit 行走路徑（PathOfTravel 只認目前檔案的牆與門）。單一模型仍用 PathOfTravel。
- 結果表與報告多一欄「模型」；雙擊可選取連結模型中的元素（暫時連結的模型檔只能顯示 ID）。
